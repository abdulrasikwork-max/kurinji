**Gotcha (seen in the V34 dry run, true of every closed list since V20):** `utf8mb4_bin` is a PAD SPACE collation, so a
value with trailing spaces (`'MBA '`) passes an `IN (...)` CHECK and is stored with its spaces. Only hand-written SQL can
do it (the backend writes enum names) and Hibernate then fails loudly when it reads the row. Patterns written with
`REGEXP_LIKE('^...$', 'c')` are not affected. A future migration that wants exact lists can use `utf8mb4_0900_bin` (NO
PAD) or add a `REGEXP_LIKE` next to the list.

prefixes `uk_`, `fk_`, `ck_`, `idx_`; FKs `ON DELETE CASCADE` (no orphans); InnoDB, utf8mb4_unicode_ci.
